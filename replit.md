# PodCap - Daily Podcast Digest

## Overview
PodCap is a full-stack web application designed to provide users with personalized daily podcast digest subscriptions. It allows users to manage their podcast selections, receive AI-generated recaps, and access detailed episode information. The project aims to deliver a seamless and intuitive experience for podcast enthusiasts, offering a unique service in the podcast consumption market. PodCap seeks to simplify podcast discovery and recap delivery, making it easier for users to stay updated with their favorite shows.

## System Architecture
**Frontend**: The user interface is built with React, Vite, Tailwind CSS, and Shadcn UI, utilizing `wouter` for routing. The design emphasizes clean white cards with subtle borders and uses Plus Jakarta Sans for display fonts. Animations are handled with `framer-motion`.
**Backend**: An Express.js server manages API requests and user sessions.
**Database**: PostgreSQL is used for data storage, accessed via Drizzle ORM.
**Authentication**: Session-based authentication is implemented, featuring a secure email-based magic link login flow.
**Pages**:
- **Home**: `/` — platform-focused landing page with hero, value props, featured podcasts, notable people, vision section, and CTAs linking to `/get-started`.
- **Get Started**: `/get-started` — dedicated signup page with the 2-step flow (choose podcasts + enter email).
- **User Management**: `/login`, `/dashboard` (manage subscriptions, delivery, billing), `/upgrade`.
- **Content Discovery**: `/podcasts` (popular directory), `/podcasts/:slug` (SEO landing pages for podcasts with recaps and episode lists), `/podcasts/:slug/episodes` (episode archive), `/podcasts/:podcastSlug/:episodeSlug` (individual episode recaps), `/podcasts/:podcastSlug/:episodeSlug/transcript` (full transcript page). **All podcast pages use shared layout components**: `PodcastPageLayout` for podcast-level pages (landing hub + archive) shares header/hero/tabs/CTA/footer/sticky-bar; `EpisodePageLayout` for episode-level pages (recap + transcript) shares header/hero/tabs/CTA/more-episodes/footer/sticky-bar. Both layouts use the shared `PodCapHeader` and `Footer` components. Changes to any shared element propagate automatically across all pages.
- **Entity Directories**: `/people` (SEO directory of notable people with profile images, mention counts + guest appearance counts, self-mention exclusion), `/people/:slug` (detail page with hero avatar, bio, social links, guest appearances first then mentions with context snippets), `/companies` (SEO directory of companies with logos, mention counts), `/companies/:slug` (detail page with logo, background, company details grid — HQ, founded, employees, market cap, CEO, industry, website — and mention episodes with context snippets). API endpoints: `/api/entities/people`, `/api/entities/people/:slug`, `/api/entities/companies`, `/api/entities/companies/:slug`. Entity data in `client/src/data/entityDirectoryData.ts`. Self-mentions excluded via `hostedPodcastSlugs` mapping. Footer uses 3-column layout: Discover / Company / Support.
- **Informational/Admin**: `/about`, `/podcast-deals`, `/updates` (changelog + feature requests), `/support`, `/privacy`, `/terms`, `/admin` (password-protected admin dashboard with tools for managing emails, users, analytics, and content templates).
**AI Integration**: Utilizes OpenAI (GPT-4o-mini) for generating daily podcast recaps and extracting sponsor deals from transcripts. Transcripts are processed from Taddy GraphQL API. AI prompts are admin-editable.
**Email System**: Uses Resend for email delivery, with a two-phase scheduler for generating and delivering daily recaps based on user preferences and timezones. An admin panel allows monitoring and management of email operations.
**Podcast Directory**: 87 podcasts with landing pages (50 original + 22 wave 2 + 15 wave 3). Each podcast has 10 AI-generated episode recaps with transcripts. Admin can batch-expand all podcasts to 50 episodes each via the "Batch Episode Expansion" panel in the admin dashboard — it fetches transcripts from Taddy and generates AI recaps with real-time progress tracking.
**Podcast Hosts**: The `podcast_hosts` table stores detailed host information per podcast: name, bio, photo URL, Twitter/X handle, LinkedIn URL, Instagram handle, website URL, and sort order. Managed via the "Hosts" tab in the admin dashboard. Podcast landing pages display rich host cards with photos and social links; falls back to the legacy `hostBios` JSONB field in `podcast_directory` when no entries exist in `podcast_hosts`.
**Episode Recap Enhancements**: Each episode recap page includes Key Topics (4-6 clickable topic chips), Top Questions (5 expandable Q&A items), and Ask About This Episode (AI-powered free-text Q&A using transcript). Key topics and top questions are generated during recap creation and stored in `landing_page_recaps` table (`key_topics text[]`, `top_questions text` JSON). The Ask feature uses `POST /api/podcasts/:slug/:episodeSlug/ask` with rate limiting (10 req/min/IP). Admin can backfill existing recaps via "Backfill Key Topics & Questions" button.
**Shop the Episode**: The Episode Recap tab includes a "Shop the Episode" section (amber-themed, ShoppingBag icon) that uses AI (GPT-4o-mini) to extract purchasable/subscribable items — books, supplements, products, gear, software, apps, courses — organically mentioned in the episode. Books and physical products get Amazon affiliate links with tag `podcap-20`. Software/apps get their actual URLs with UTM params (`utm_source=podcap&utm_medium=referral&utm_campaign=resource`). Sponsor names are passed to the AI prompt so it explicitly excludes all paid sponsors. Data cached in `landing_page_recaps.resources` (text/JSON column). API: `GET /api/podcasts/:slug/:episodeSlug/resources` with in-flight deduplication. Cross-links between Sponsors and Shop the Episode sections.
**Episode Guests Tab**: Each episode page has three tabs: "Episode Recap", "Full Transcript", and "Guests" (route: `/podcasts/:slug/:episodeSlug/guests`). The Guests tab uses AI (GPT-4o-mini) to identify guests from the transcript and provides: full name, professional title, detailed biography, social media links (Twitter/X, LinkedIn, Instagram, website), and topics discussed. Data is cached in `landing_page_recaps.guests` (text/JSON column). API: `GET /api/podcasts/:slug/:episodeSlug/guests` with in-flight deduplication. Frontend includes JSON-LD Person schema for SEO, safe URL validation, and XSS-safe JSON-LD serialization. Empty state shown for episodes with no guests.
**Show Notes**: The `landing_page_recaps.show_notes` text column stores the raw HTML show notes from Taddy (sourced from Apple Podcasts/iTunes). Contains rich data including sponsor links, book/resource recommendations, timestamps/chapters, and external links. Fetched via `searchEpisodeShowNotes()` in `taddyClient.ts` which searches Taddy by podcast+episode name and returns the `description` field. Automatically fetched for new episodes during daily recap generation and batch expansion. Admin can backfill existing episodes via "Backfill Show Notes" button in admin dashboard (`POST /api/admin/backfill-show-notes`). This data can be used to enhance sponsors, guests, resources, and other features.
**Episode Recap Section Titles**: Quick Summary (was TLDL), Key Takeaways (was Key Insights), Chapters (was Episode Breakdown), Quick Q&A (was Top Questions), Podcast Chat (was Ask AI, has sparkle AI badge), Sponsors (unchanged).
**Podcast-Level AI Features**: The "Ask About This Podcast" tab on podcast pages includes: (1) Top Questions accordion — 5 SEO-friendly Q&As generated via AI from episode summaries, cached in `podcast_top_questions` table (slug, questions JSON, generated_at), generated on first visit via `GET /api/podcasts/:slug/top-questions` with rate limiting and in-flight deduplication; (2) AI Search — free-text Q&A across all episode transcripts via `POST /api/podcasts/:slug/ask` with ILIKE search + OpenAI, rate limited 10 req/min/IP. The "Search Transcripts" tab provides keyword search across transcript segments.
**RSS Feeds**: Public RSS endpoints at `/rss/all` (all recaps) and `/rss/feed/:slugKey` (custom feeds). Custom feeds are managed via the admin dashboard RSS Feeds tab (`rss_feeds` DB table). Each RSS item includes podcast name, episode title, TL;DL summary, full recap with key insights and quotes, artwork, and links — designed for bot consumption (e.g., auto-posting to Twitter). Feeds are cached for 15 minutes.
**Database Indexes**: Custom indexes exist for performance at scale: `idx_landing_page_recaps_slug_date` (composite on slug + publish_date DESC), `idx_transcript_segments_podcast_text` (podcast_slug), plus existing unique constraints. The recaps API supports server-side pagination via `?limit=N&offset=N` (returns `{recaps, total, limit, offset}`) — existing callers without `offset` still get a plain array for backward compatibility.
**Design System**: Features a consistent design language with `max-w-3xl` for content, `bg-white border border-black/[0.06] rounded-2xl` for cards, `rounded-xl font-display font-bold` for buttons, and `h-11 or h-12, rounded-xl, border-black/[0.08]` for inputs. All pages are SEO-optimized with dynamic meta tags, OG tags, canonical URLs, and JSON-LD schema.
**Typography**: Only two Google Fonts are loaded: Inter (body text via `--font-sans`) and Plus Jakarta Sans (headings via `--font-display`). Imported in `client/src/index.css`. The `index.html` preconnects to Google Fonts but does not load any font stylesheet directly (to avoid duplicate loading). Minimum font size across public-facing pages is `text-xs` (12px), with content text at `text-sm` (14px) or larger for senior-friendly readability. Only decorative section badge numbers in episode recaps use `text-[11px]`.

## External Dependencies
- **Stripe**: Integrated for payment processing and subscription management, leveraging Replit's `stripe-replit-sync` for webhook and data synchronization.
- **OpenAI**: Used for AI-driven podcast recap generation and deal extraction from transcripts.
- **Taddy GraphQL API**: Provides podcast transcription services, used for generating accurate recaps and for the server-rendered transcript pages.
- **iTunes Search API**: Powers the podcast search functionality for user subscription selection.
- **Resend**: The chosen email service provider for sending daily podcast digests and magic links.
- **`connect-pg-simple`**: Used for storing Express sessions in PostgreSQL.
- **`framer-motion`**: Library for animations in the frontend.
