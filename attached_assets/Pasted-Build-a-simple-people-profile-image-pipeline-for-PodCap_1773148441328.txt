Build a simple people profile image pipeline for PodCap, similar in spirit to Logo.dev, but for people.  Goal Each /people/[slug] page should have a reliable profile image, with a clean fallback system when no real image is available.  High-level approach For each person, try image sources in this order: 	1.	Wikipedia / Wikimedia Commons 	2.	X / Twitter profile image if we have a known handle 	3.	Fallback generated avatar if no photo is available  Important Do not try to scrape random names from the web with no confidence. Only do this for people that already exist as canonical people in our database.  Data model For each person record, support fields like: 	•	name 	•	slug 	•	image_url 	•	image_source 	•	twitter_handle 	•	wikipedia_url 	•	company 	•	role  Add: 	•	image_status with values like pending, resolved, fallback 	•	image_last_checked_at  Resolution logic When a person page is created or updated: 	1.	Check if image_url already exists 	•	If yes, use it 	•	If no, continue 	2.	Try Wikipedia / Wikimedia 	•	If the person has a known Wikipedia page, fetch the lead image 	•	Save the image URL and mark source as wikimedia 	3.	If no Wikipedia image is found, try X / Twitter 	•	Only do this if we already have a trusted twitter_handle 	•	Pull the profile image and save it 	•	Mark source as twitter 	4.	If no real image is found 	•	Generate a fallback avatar 	•	Use initials or a consistent generated avatar style 	•	Mark source as fallback  Do not 	•	Do not use low-confidence entity matching 	•	Do not guess random social profiles 	•	Do not scrape arbitrary websites for now 	•	Do not overwrite a manually approved image  Image normalization Normalize all resolved profile images into a consistent format: 	•	square 	•	centered crop 	•	target size: 400x400 	•	optimized for web delivery 	•	stored in our own image path / CDN if possible  Example output path: 	•	/images/people/sam-parr.jpg 	•	/images/people/elon-musk.jpg  If storing remote URLs first is easier, that is fine for V1, but structure it so we can later mirror and cache locally.  Fallback avatar requirements If no real image is found: 	•	show a high-quality generated avatar or initials tile 	•	keep it visually consistent across the site 	•	use deterministic output so the same person always gets the same fallback  UI behavior On /people/[slug] pages: 	•	always show a profile image area 	•	never show broken or missing image icons 	•	if image_source = fallback, still render it cleanly  Admin / ops support Add an internal way to see: 	•	people missing real images 	•	people using fallback avatars 	•	people whose image lookup failed 	•	people with manually set images  This can be a simple admin list for now.  Implementation priority V1: 	•	support existing canonical people only 	•	Wikipedia/Wikimedia lookup 	•	fallback avatar 	•	consistent rendering on people pages  V2: 	•	support trusted X handles 	•	local caching / mirroring 	•	admin override for wrong images  Main principle This should be a conservative, high-confidence image pipeline. It is better to show a fallback avatar than the wrong person’s face.  Goal for PodCap Make /people pages feel complete and trustworthy, while keeping the system scalable and low-maintenance.
